# 超星字体混淆处理（v2.2.0）

## 设置入口

控制台 → **AI 接口配置** → **超星字体混淆处理策略**：

| 配置 | 默认 | 行为 |
| --- | --- | --- |
| `cxFontStrategy` | `table` | `table` 查现有指纹表，或 `vision` 图片视觉；手动互斥选择，不自动回退 |
| `cxVisionUseMain` | `true` | 视觉复用主解题 API，或设为 `false` 使用独立视觉 API |
| `cxVisionBaseUrl` | 空 | 独立模式的 Base URL |
| `cxVisionApiKey` | 空 | 独立模式的密钥 |
| `cxVisionModel` | 空 | 独立模式的模型名称 |

策略和来源选择实时保存；API 三个参数需点击“保存 API 配置”。切换模式只隐藏/禁用独立参数输入，不清除已保存值，也不把两套 API 参数混合使用。独立模式缺少任何一项即失败，不回退主 API。

视觉 API 必须支持 OpenAI 兼容的图片输入和 `response_format: {type: "json_object"}`。复用模式也有相同要求。“测试 API 连接”仍只验证主解题 API 的文本响应，不是图片能力测试。

## 数据流

```text
题目所属 Document 中的内联 @font-face + .font-cxsecret 文本
                       ↓
           按 Document 和实际字体分组
                       ↓
        ┌──────────────┴────────────────┐
        │ table                         │ vision
        │ Typr 解析字体                 │ 原生 FontFace 加载到题目文档
        │ 字形路径 JSON 的 MD5 末 8 位  │ Canvas 编号汉字图（每批最多 40 字）
        │ 查内置 20220515.1 指纹表       │ 所选视觉 API 仅转写，不解题
        └──────────────┬────────────────┘
                       ↓
          混淆字符 → 普通汉字的内存映射
                       ↓
      只读 readText：仅还原标记范围内的文本
                       ↓
      既有题目 JSON → 主解题模型 → 校验与填入
```

视觉图片只包含该批编号和单字，不上传整页截图、账号、课程链接或输入框。独立模式下，视觉 API 收到字形图片，主解题 API 收到还原后的题目文本；复用模式下两类请求发往同一套已保存配置。密钥会随相应请求发送给所配置的 API。

没有修改宿主的文字节点、`innerHTML`、字体样式或 class。因此不会为了还原而重建事件节点，也不会因移除 class 后仍残留 style 导致重复解密。切换策略可重新识别原始字体；没有持久化视觉结果或图片。

## 接入范围与安全条件

- 超星章节测验、独立 `.questionLi` 作业/考试、视频随堂弹题均先准备字体读取器。
- 普通题目没有 `.font-cxsecret` 汉字时，不解析字体、不发识图请求，保留原有文本答题流程。
- 选择题仍按选项顺序填入；判断题返回“正确/错误”时使用已还原选项匹配，不再拿 DOM 原始乱码匹配。
- 查表未命中、字体不明确、图片加载失败、API 失败、返回缺字/重复编号/非法字形时，失败的题目集合不发送解题请求，不自动提交。章节测验/独立作业可按原流程暂存；视频弹题不点击提交。
- 所有字形编号必须完整且唯一，识别结果必须恰好一个汉字；不从散文中猜测、不用缺失项补齐，也不自动换策略。
- 识别前后、题目读取和答案返回后会校验题目连接状态、混淆文字、字体样式和文档地址。页面或字体变化时拒绝晚到结果。
- 策略、视觉来源或相关 API 配置变化会使旧识别/答案请求结果失效；关闭相应助手也会阻止后续处理。已发出的网络请求不保证能从服务端取消，仍可能计费。切换后需要重新触发作答。

**合法 JSON 不代表识别正确。** 视觉模型可能把某汉字识别成另一个汉字，现有表也依赖固定字形/截断指纹。默认自动提交设置没有被本功能改动，使用前建议关闭自动提交，核对还原后的题目及答案。

## 已知边界

1. 目前只支持 `.font-cxsecret` 范围内的汉字和题目文档中的内联 Base64 字体。外链字体、字体归属不明确、同名字体含多份不同数据会拒绝；不擅自下载未知字体。
2. 查表依赖固定版本 Typr 的路径序列化及旧指纹表，并非通用 OCR；字形坐标变化可能失配。字体未包含的汉字按普通系统回退文字保留。
3. 视觉策略依赖浏览器原生 FontFace/Canvas，不依赖截图扩展权限。字体加载上限 15 秒，API 请求上限沿用 45 秒；单页最多 2,000 个分组去重汉字，单字体最多 8 MiB。
4. 不做整道图片题 OCR，也不增加公式、图片选项或跨域页面读取能力。不能把当前功能当成所有图片题都已支持。
5. 不改变现有答题模型、四题批协议及题型限制；视觉识图仍有额外延迟和费用。

## 代码与依赖

- [`src/modules/chaoxing/cxFont.js`](../src/modules/chaoxing/cxFont.js)：两种字符映射实现与只读接口 `CxFont.prepare(roots, config, {cancelled})`，返回 `readText` / `assertCurrent`。
- [`src/api/openai.js`](../src/api/openai.js)：`resolveCxVisionConfig`、`requestCxGlyphRecognition`，以及原有文本批请求。
- [`src/ui/uiController.js`](../src/ui/uiController.js)、[`src/config.js`](../src/config.js)：控制台与完整配置快照。
- [`src/vendor/README.md`](../src/vendor/README.md)：指纹表和 Typr/MD5 固定版本、原始哈希、封装差异、许可边界。
- [`现有插件源码调研`](research/chaoxing-font-plugins.md)：历史参考；本实现没有直接复制原扩展的 DOM 改写算法。

依赖已包含在构建中，不依赖 `reference/` 被忽略的原包，也不从 CDN 下载映射表或运行远程脚本。第三方告知保留在源文件和 [`LICENSES.txt`](../src/vendor/LICENSES.txt)；表的作者/版本/MIT 声明已保留，独立版权告知来源的未决项也有记录。

```bash

npm test

```

覆盖：标记与普通文本隔离、多文档字体分组、查表失败、40 字分批、配置快照与保存、fetch/GM 多模态请求、严格 JSON、取消与晚到结果、章节/作业/视频接入、判断题选项匹配、字体加载超时。

另外已用本地合成 TTF、模拟视觉响应，在独立 Edge 无头页面检查原生 FontFace/Canvas、控制台独立配置显示、只读 DOM 和真实 Typr 未命中分支。**未向真实视觉服务发送测试图片，也未验证当前超星真实字体的识别准确率**；本地页面样本不包含 `.font-cxsecret` 元素，不能代替该项验证。
